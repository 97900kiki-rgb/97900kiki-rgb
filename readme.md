# 관상가 아솔 (GwangsangWebAPP)

**v4.0.0** (2026-09-03) · FastAPI + 손으로 짠 화면

사진 한 장으로 관상을 풀이해 주는 웹앱. 조선 팔도를 떠돌던 전설의 관상가
'아솔'이 얼굴을 보고 성별·나이대·직업을 짚어 준 뒤 관상 풀이를 들려준다.
다시 찾아오면 **얼굴로 알아보고** 지난 기록과 견주어 준다.

- 배포: https://asoul.ssirn.co.kr (svr3, Cloudflare 터널)
- AI 백엔드: **사내 LLM 서버** (OpenAI 호환 API, 비전 모델 `gemma3:27b`)
- 판번호는 `server.py` 의 `__version__` **한 군데**에만 있다.
  화면(`static/index.html` 의 `.ver`)과 이 문서가 그것을 따른다.
  `GET /healthz` 가 `{"ok":true,"version":"..."}` 로 알려 준다.

## 구성

| 파일 | 하는 일 |
|---|---|
| `server.py` | FastAPI. `/api/prepare` `/api/read`(SSE) `/api/finish` `/api/verify/*` `/api/notice` `/healthz` |
| `static/` | 화면 전부 — `index.html` · `app.css` · `app.js` |
| `reading.py` | 프롬프트·모델 고르기·응답 파싱. 화면과 떼어 두었다 |
| `faceutil.py` | 얼굴 찾기·정렬·자르기·특징값(SFace)·메시 그림 |
| `leads.py` | 남긴 사람 보관 · 얼굴로 알아보기 · 동의 문구 (SQLite) |
| `mailer.py` | 감정서 메일 (SMTP 릴레이) |
| `llm_client.py` | 사내 LLM 서버 클라이언트 |
| `deploy/` | `Dockerfile` · `entrypoint.sh` · `compose.yml` — **사이트 루트에 두는 것들** |
| `tests/` | `python tests/test_leads.py` — 임시 DB 로 89가지를 확인한다 |

## Streamlit 을 걷어냈다 (v4.0.0)

세 가지가 겹쳤다.

1. **버튼 크기와 자리를 우리가 정할 수 없었다.** 붙박이 액션바 하나 두려고
   `st-key-` 클래스를 뒤져 CSS 로 비틀어야 했다.
2. **위젯이 화면에서 사라지면 상태까지 버렸다.** 켜 둔 체크가 저절로 풀렸다.
3. ★ **연결이 끊기면 모든 것이 날아갔다.** 로그에
   `Session ... is already connected! Reconnecting` 뒤로 스크립트가 처음부터
   다시 도는 것이 찍혔다. 감정서를 쓰는 동안 앞단이 조용한 연결을 끊은 것이다.
   그때마다 사진도 감정서도 사라지고 촬영 화면으로 돌아갔다.

지금은 감정서를 **SSE 로 흘려보낸다.** 흐르는 동안 연결이 살아 있으므로 끊기지
않고, 진행 막대도 실제 진행에 맞춰 움직인다.

## 판번호를 정적 파일에 붙인다

`/` 가 `index.html` 을 읽어 `app.js?v=<mtime>` 로 바꿔 내보낸다.
붙이지 않았을 때 **고쳐 올려도 브라우저가 옛 `app.js` 를 계속 썼다.** 서버는 새
코드인데 화면만 옛것이라, 반영이 안 된 줄 알고 같은 곳을 몇 번이나 다시 고쳤다.

## 감정서는 두 단계다 (v2.8.0)

| | 분량 | 양식 | 언제 |
|---|---|---|---|
| 맛보기 | 600자 안팎 | `SHORT_FORM` — 5개 항목 | 사진이 들어오면 바로 |
| 전체 | 1200자 이상 | `PROMPT_FORM` — 15개 항목 | [자세히 보고 메일로 받기] |

⚠️ **맛보기 분량을 바꾸려면 양식(`SHORT_FORM`)을 고쳐야 한다.**
큰 양식에 "600자로 써라"라고만 지시했더니 1,600자가 나왔다. 항목이 열다섯 개라
한 문장씩만 써도 그 분량이 되기 때문이다. 지시가 아니라 양식이 분량을 정한다.
(둘 다 `reading.py` 에 있다.)

## 다시 오시면 알아본다 (v4.0.0)

얼굴 특징값(SFace, 숫자 128개)을 담아 두었다가 다음에 오시면 코사인으로 찾는다.
같은 사람 0.974 / 다른 사람 0.089, 문턱 **0.363**(OpenCV 권장치).

- **정렬이 정확도를 좌우한다.** 상한을 45도로 두었더니 옆으로 누운 사진에서
  같은 사람 점수가 **0.064** 였다. 89도로 푸니 **0.974** 가 됐다.
- 이력을 여는 열쇠는 **얼굴뿐이다.** 사람을 이을 때는 연락처도 쓰지만(중복 등록
  방지), 그 `person_id` 로 지난 감정서를 열면 **남의 번호를 적은 사람에게 남의
  이력이 열린다.** 인사와 이력은 `find_person()` 이 돌려준 것으로만 한다.
- 얼굴은 사람당 **하루 한 장**만 담는다. 한 번에 여러 번 찍어도 거의 같은 장만
  쌓일 뿐이다. 보고 싶은 것은 날짜를 사이에 둔 변화다.

## 본인 확인 문답 (v4.0.0)

얼굴 점수가 문턱 아래 애매한 자리(0.22~0.363)에 후보가 있을 때만 연다.
남기신 이야기와 지난 걸음 기록을 밑천 삼아 예/아니오 질문 셋을 짓되,
**맞는 것과 일부러 틀린 것을 섞는다.** 본인이면 틀린 대목을 바로잡고,
사칭하는 사람은 그냥 "네" 하고 넘어가 걸러진다.

⚠️ **되묻는 질문 자체가 이야기의 대부분을 흘린다.** "따님이 고3 때 자퇴한 적
있소?" 는 이미 '자녀·자퇴'를 알려 준다. 그래서 **두 번 틀리면 더 묻지 않는다.**
그리고 이야기 원문을 **바깥 LLM 에 보내지 않는다** — 동의서에 "이 서비스 밖으로
내보내지 않는다"고 적어 두었기 때문이다.

## 개인정보 — 적어 둔 대로 코드도 그렇게 (v4.0.0)

필수 동의가 곧 서비스 조건이 된 이상, 필수 항목은 **그 서비스에 꼭 필요한
것**으로만 좁혀야 한다(개인정보 보호법 제16조 3항).

| | 항목 | 왜 |
|---|---|---|
| **필수** | 이름 · 이메일 | 감정서를 지어 보내는 데 실제로 쓴다 |
| 선택 | 휴대전화번호 | 메일 보내는 데 번호는 쓰이지 않는다 |
| 선택 | 얼굴 특징값 · 사진 · 감정서 · 기분/컨디션 · 확인용 이야기 | **만드는 데**는 필요해도 **남겨 두는 데**는 아니다. 보관은 "다음에 견주어 보기" 라는 다른 목적이다 |

- 얼굴 특징값은 법에서 **민감정보**다. 그래서 체크박스를 따로 둔다.
- **체크를 거두시면 그때까지 쌓인 것을 곧바로 지운다** — 특징값·사진·지난
  감정서·기분·이야기 모두. 동의 철회는 "앞으로 안 모음"이 아니라
  "모아 둔 것도 없앰"이어야 한다.
- 보유기간은 **마지막 방문일**로부터 365일. 가입일 기준으로 하면 한 해째 계속
  오시는 분을 한창 쓰시는 중에 지운다. 지울 때 `people`·`faces`·`visits`·`leads`
  가 함께 사라진다.
- 건강을 **진단하지 않는다**(`leads.NO_MEDICAL`). 웰니스 표현만 쓴다.
- 이 약속들은 `tests/test_leads.py` 가 실제로 확인한다.

## 배포

`deploy/` 의 셋은 **사이트 루트**(`/data/sites/gwansang.ssirn.co.kr/`)에 두고,
이 저장소는 그 아래 `app/` 이 된다. `Dockerfile` 의 `COPY app/...` 가 그 짜임이다.

```
git archive HEAD | ssh svr3 'tar x -C /data/sites/gwansang.ssirn.co.kr/app'
ssh svr3 'cp /data/sites/gwansang.ssirn.co.kr/app/deploy/* /data/sites/gwansang.ssirn.co.kr/   && cd /data/sites/gwansang.ssirn.co.kr && docker compose build && docker compose up -d'
```

⚠️ **healthcheck 주소를 코드와 함께 고칠 것.** v4.0.0 전까지 `compose.yml` 이
Streamlit 의 `/_stcore/health` 를 가리켜 **11번 연속 실패, unhealthy** 였다.
사이트는 멀쩡히 돌았기 때문에 아무도 몰랐다. 지금은 `/healthz` 다.

⚠️ 모델 둘(`face_landmarker.task` 3.8MB, `sface.onnx` 38.7MB)은 **구울 때** 받아
이미지에 굽는다. 실행 중에 내려받으면 첫 손님이 그 시간을 기다리고, 바깥이
막히면 아예 못 쓴다. SFace 는 `raw.githubusercontent` 가 아니라
`media.githubusercontent.com/media/...` 에서 받아야 한다(앞쪽은 LFS 포인터다).

## 메일 발송 (`mailer.py`)

전체 감정서를 메일로도 보낸다. **SMTP 릴레이가 반드시 필요하다.**

서버(svr3)의 공인 IP 는 역방향 이름(PTR)이 없어서 직접 보내면 받는 쪽이
스팸으로 거르거나 거부한다(네이버는 25번 포트 자체가 막혀 있다). 릴레이를
쓰면 보내는 주체가 그쪽 서버가 되므로 정상 도착한다.

`app.env` 에 넣는다:

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=보내는계정
SMTP_PASS=앱비밀번호
SMTP_FROM=아솔 <asol@ssirn.co.kr>
SMTP_MODE=starttls        # starttls | ssl | plain
```

설정이 없으면 **보내지 않고 그렇다고 화면에 말한다.** 성공한 척하지 않는다.
남긴 주소는 발송 성공 여부와 무관하게 `data/emails.jsonl` 에 기록된다
(컨테이너 볼륨이라 이미지를 다시 구워도 남는다. `.gitignore` 로 저장소에서는 제외).

## 알려진 것

- **인앱 브라우저 차단은 없다.** v2.8.0 에서 지웠다. `st.markdown` 으로 넣은
  `<script>` 는 브라우저 규격상 실행되지 않아 처음부터 동작한 적이 없고,
  화면 맨 위에 `}` 한 글자만 흘리고 있었다. 필요하면 새로 만들어야 한다.

## 감정서 메일 (v2.9.1)

얼굴 사진(세로 타원)과 기본 분석 결과가 함께 실린다.

- 사진은 **이미지 자체를 타원으로 잘라서** 넣는다. 메일에서 CSS `border-radius` 는
  믿을 수 없다(Outlook 이 무시). 투명 PNG 도 클라이언트마다 배경이 달라
  지저분해지므로 흰 바탕에 올려 불투명하게 굽는다.
- 붙이는 방식은 **CID 첨부**다. Gmail 은 `src="data:..."` 를 지우므로
  데이터 URI 로는 사진이 안 보인다.
- 얼굴이 가운데보다 위에 있어 세로로 자를 때 위를 조금 더 남긴다(0.38).

## 변경 이력

### v4.0.0 (2026-09-03) — Streamlit 을 걷어내고 다시 짰다

밤새 두 세션이 나눠 지었다. 화면·얼굴 쪽은 집 PC 세션이, DB·개인정보 쪽은
학교 PC 세션이 맡았다.

**① Streamlit 제거.** 위 「Streamlit 을 걷어냈다」 참조. 특히 감정서를 쓰는
동안 연결이 끊겨 사진도 결과도 통째로 날아가던 것이 결정적이었다.
이제 FastAPI + SSE 이고, 화면은 `static/` 에 우리가 짰다.
`streamlit_app.py`·`.streamlit/`·`components/autocam/` 을 지웠다(이력에 남는다).
쓰지 않게 된 옛 GitHub Pages 용 `index.html`·`public/og-image.png` 도 함께 지웠다.

**② 다시 오시면 알아본다.** SFace 특징값 · 얼굴 정렬(±25도 → 0.9도 이내) ·
본인 확인 문답 · 기분/컨디션 기록. 표 셋(`people`·`faces`·`visits`)을 더했고
기존 `leads` 는 되돌릴 자리로 그대로 두었다.

**③ 개인정보를 적어 둔 대로 맞췄다.** 필수를 이름·이메일로 좁히고, 사진·감정서·
이야기를 선택 동의 쪽으로 내렸다. 필수 동의 체크박스는 없애고 버튼 문구로
갈음했다(그 버튼을 누르는 것이 동의다). `[화면으로만 보기]` 를 없앴으므로
`NOTICE` 에서 그것을 가리키던 대목도 지웠다.

**④ 고친 것들**
- ★ `compose.yml` 의 healthcheck 가 Streamlit 주소를 가리켜 **컨테이너가
  unhealthy** 였다(11번 연속 실패). 사이트가 멀쩡히 돌아 아무도 몰랐다.
- ★ `Dockerfile`·`entrypoint.sh`·`compose.yml` 이 **어디에도 추적되지 않았다.**
  사이트 루트에 있어 이 저장소에도, `/data/.gitignore` 때문에 `svr3-infra`
  에도 없었다 — 서버를 다시 세우면 재현이 안 됐다. `deploy/` 로 들여왔다.
- ★ 정적 파일에 판번호(`app.js?v=mtime`). 없어서 고쳐 올려도 브라우저가 옛
  코드를 계속 썼고, 반영이 안 된 줄 알고 같은 곳을 여러 번 고쳤다.
- `leads.pack_embedding` 의 `vec or []` 가 numpy 배열에서 터졌다
  (배열은 참·거짓을 물을 수 없다). `vec is None` 으로 바꿨다.
- leads 줄을 사람과 잇는 backfill 이 `WHERE phone=?` 였다. 전화번호가 선택이
  되면서 **번호를 안 적은 다른 분들 줄까지 한 사람에게 몰아 붙었다.**
- 진행 막대를 글자 수가 아니라 걸린 시간으로. 1,200자를 시켰는데 2,655자를
  써서 200%가 되어 "다 찼는데 53초 남았소"가 나왔다.
- 걸음 수를 `visits+1` 이 아니라 실제 기록 수로. 그 방문이 담기지 않으면
  다음에도 또 "2번째"라 늘 같았다.

### v3.3.0 (2026-09-02) — 손에 잡히게

**① 카메라 버튼을 우리말로.** Streamlit 이 "Take Photo"/"Clear photo" 로 고정해 둔다.
특히 **"Clear photo" 가 "사진을 지운다"로 읽혀** 다시 찍는 버튼인 줄 모른다.
두 상태가 같은 버튼이라 CSS 로는 못 가려, 메타태그 주입과 같은 방식(MutationObserver)으로
글자만 갈아 끼운다. 바꾼 글자는 `MAP` 에 없으므로 관찰이 스스로를 다시 부르지 않는다.

**② 미리보기를 고른 자리로 올리고 두 장으로.** 전에는 촬영 위젯이 빈 상자로 남고
얼굴은 한참 아래에 떴다. 이제 사진 바로 밑에 나란히 둔다.

| 왼쪽 | 오른쪽 |
|---|---|
| 감정서에 담길 얼굴 (타원) | 아솔이 얼굴로 본 자리 (네모) |

**결과와 근거를 함께 보여 준다.** 엉뚱한 데를 잡으면 바로 알아채고 다시 찍을 수 있다.
`faceutil` 의 상자 계산을 `_crop_box()` 로 빼고 `boxed_png()` 를 더했다 — 네모가 제자리에
오려면 `face_crop` 과 **같은 상자**를 알아야 하기 때문이다. 기존 함수의 출력은
바이트까지 그대로인 것을 확인했다(`oval_png`·`face_jpeg`·`face_crop`).
얼굴 찾기가 세 번 돌게 되어 `@st.cache_data` 로 사진 바이트를 열쇠 삼아 캐시했다.

**③ [↩️ 처음으로].** 감정서 맨 아래. 사진·결과·나이·성별 선택까지 지우고 처음 화면으로
돌아간다. 전에는 새로고침밖에 길이 없었고 그마저 고른 값이 남아 헷갈렸다.

### v3.0.0 (2026-09-02) — 주소 변경 · 메일 발송 · 개인정보 수집 · 얼굴 맞춤

하루에 몰아서 한 작업이라 v2.8.0 부터 여기까지를 한 항목에 적는다.
MINOR 가 9 에 닿아 MAJOR 를 올렸다.

주소가 **`asoul.ssirn.co.kr`** 이 되었다. `gwansang` 이 치기 어렵다는 요청이고,
메일 주소 `asoul@ssirn.co.kr` 과도 짝이 맞는다. 옛 주소도 당분간 함께 살려 둔다.

#### 나이를 물어본다

**문제**: 60대인 사람을 40대로 보는 일이 잦았다. 사진만으로 나이를 맞히는 것은
원래 어렵다.

**조치**: 연대(10~90대)와 구간(초·중·후반)을 직접 고를 수 있게 했다. 고른 값이
있으면 그것으로 감정하고, 아솔의 추정과 다르면 **숨기지 않고 함께 보여 준다** —
"아솔은 30대 초반으로 보았소만, 일러 주신 나이로 감정하였소". 그래야 왜 물었는지
납득이 간다. 조사는 `_euro()` 가 받침을 보고 로/으로를 고른다.

#### 감정서가 두 단계가 되었다

맛보기(600자) → **[전체 감정서 보기]** → 전체(1200자 이상) + 메일 발송.

**문제**: "600자로 써라"를 프롬프트 맨 앞과 항목 지침 양쪽에 넣었는데도 배포된
앱에서 재 보니 **1,654자**였다(그 전은 1,585자).

**원인**: 지시를 안 듣는 게 아니었다. 양식에 큰 항목이 **열다섯 개**라 한 문장씩만
써도 그 분량이 나온다. 물리적으로 불가능한 것을 요구하고 있었다.

**조치**: 맛보기용 짧은 양식(`SHORT_FORM`, 다섯 항목)을 따로 뒀다.
**분량은 지시가 아니라 양식이 정한다.**

**검증**: 실제 얼굴 사진으로 621자.

이를 위해 감정서를 그리는 코드를 버튼 블록 **밖**으로 옮겼다. 전에는 버튼 안에서만
그려서 화면을 다시 그리면(= 자세히 보기를 누르면) 결과가 통째로 사라졌다.

#### 메일 발송

**제약**: 이 서버는 인바운드 25·587·993 이 전부 막혀 있고 공인 IP 에 역방향
이름(PTR)이 없다. 직접 보내면 스팸으로 걸러지고 네이버는 아예 거부한다.
**설치의 문제가 아니라 도달의 문제**라 SMTP 릴레이가 반드시 필요하다.

**조치**: SendGrid 릴레이(`smtp.sendgrid.net:587`)로 보낸다. 도메인 인증(SPF·DKIM)을
해 두어 `아솔 <asoul@ssirn.co.kr>` 이름으로 나간다. 설정이 없으면 보내지 않고
그렇다고 말한다 — 성공한 척하지 않는다.

**검증**: 실제로 보내 **스팸함이 아니라 받은편지함**에 몇 초 만에 도착하는 것을
확인했다. 자세한 경위는 서버의 `/data/sites/_메일서버-검토.md`.

⚠️ 무료 등급은 **하루 100통**. 넘으면 그날은 못 보낸다.

#### 개인정보 수집

[메일로 받기] 를 누르면 **이름 · 이메일 · 휴대전화번호 · 얼굴 사진**을 받는다.
`leads.py` 가 SQLite 에 담는다.

**요점은 화면에 적은 약속을 코드로도 지키는 것이다.**

- 동의가 없으면 `save()` 가 **거부한다.** 화면 코드가 바뀌어도 이 규칙은 남는다.
- 보유 기간(기본 365일)이 지난 줄은 `init()` 이 **실제로 지운다.** 적어만 두고
  안 지우면 그게 제일 나쁘다.
- 버튼을 둘로 나눴다. **[화면으로만 보기]** 로 가면 아무것도 받지 않는다 —
  동의 거부가 실제로 가능해야 고지가 형식이 아니게 된다.

⚠️ 사진을 보관하게 되면서 **화면 문구도 함께 고쳤다.** 전에는 "모든 사진은 분석 후
즉시 삭제됩니다" 였는데 그대로 두면 거짓말이 된다.

**검증**: 경계값으로 굴려 이름 1글자·전화 형식 오류·동의 없음이 각각 거부되는 것과,
800일 전 줄을 넣고 `init()` 을 불러 실제로 지워지는 것을 확인했다.

#### 감정서 메일에 얼굴 사진

**문제**: 처음에는 사진이 동그라미 밖으로 삐져나왔다.

**원인**: 얼굴 위치를 보지 않고 사진 한가운데를 잘랐다. 얼굴이 가운데가 아니면
그대로 어긋난다. 게다가 상자가 사진 밖으로 나가면 PIL 이 그 부분을 검게 채운다.

**조치**: `faceutil.py` 가 얼굴을 찾아(opencv Haar) 폭의 1.55배만 남기고, 상자가
사진 밖으로 나가면 **안으로 밀어 넣는다.** 메일과 DB 가 **같은 기준으로** 자르도록
한 군데에 모았다.

메일 쪽 제약 두 가지:
- CSS `border-radius` 는 믿을 수 없다(Outlook 이 무시) → **이미지 자체를** 타원으로 굽는다.
- Gmail 은 `src="data:..."` 를 지운다 → **CID 첨부**여야 사진이 보인다.

배경 분리(rembg 등)는 하지 않았다. 400MB 가 넘고 요청마다 수 초가 드는데, 얼굴을
틀에 꽉 채우면 배경이 거의 남지 않아 보이는 결과가 거의 같다.

DB 에는 타원이 아니라 **마스크 없는 크롭(480x640 JPEG)** 을 넣는다. 마스크는 보여
주는 방식일 뿐이고, 다른 용도로 재사용하려면 가려지지 않은 쪽이 쓸모 있다.

**검증**: 실제 얼굴 사진으로 끝까지 돌려, 얼굴이 타원에 꽉 차고 머리도 잘리지 않는
것과 DB 에 48,457 바이트가 담기는 것을 확인했다.

### v2.7.0 (2026-09-02) — 생성 중 진행 표시

**문제**: 1200자 감정서는 30~70초가 걸리는데, 그동안 화면은 "장군신 소환 중..." 에서

- 진행바가 85% → 99% 로 차오르고
- `🖌️ GEMMA3 장군신이 감정서를 쓰는 중… 1,234자 · 28초`

- 화면 갱신은 **0.35초에 한 번**으로 제한(너무 잦으면 오히려 느려진다)

### v2.6.0 (2026-09-01) — AI 백엔드를 사내 LLM 서버로 완전 교체

**무엇이 문제였나**

1. Google Gemini API 의존. 무료 할당량(429)을 자주 넘겨 "모든 장군신이
   휴식 중"으로 떨어지고, Hugging Face 대체 경로도 410 으로 죽어 있었다.
2. 윈도우에서 로컬 실행하면 앱이 화면을 그리다 말고 죽었다.

**왜 그랬나**

2번이 특히 고약했다. 콘솔 인코딩이 cp949 인데 `print("❌ ...")` 의 이모지가
cp949 로 인코딩되지 않아 `UnicodeEncodeError` 가 났다. 하필 그 print 가
`except` 블록 안에 있어서, **원래 에러를 보고하려던 코드가 스스로 터지며
진짜 원인까지 가려 버렸다.** 겉으로는 "요소 5개만 그리고 멈춤"으로 보인다.

**어떻게 고쳤나**

- `llm_client.py` 신규. OpenAI 호환 `/v1/chat/completions` 래퍼이며, 응답
  객체가 `.text` 를 그대로 갖도록 맞춰 기존 UI 코드 1,000여 줄은 손대지 않았다.
- Gemini · Hugging Face 경로 전부 제거 (`genai` 잔재 0건 확인).
- 파일 최상단에서 stdout/stderr 을 UTF-8 로 고정. 다른 import 보다 먼저 수행한다.
- 비전 모델만 사용. 관상은 사진을 봐야 하므로 텍스트 전용 모델은 쓸 수 없다.

**모델 선정 근거 (실측)**

서버의 7개 모델 중 이미지를 볼 수 있는 것은 2개뿐이었다.

| 모델 | 결과 |
|---|---|
| `gemma3:27b` | 24초에 정상 응답, 요구 형식 4개 항목 모두 정확 → **채택** |
| `qwen3-vl:32b` | 126초를 끌다가 HTTP 524 → 제외 |

524 는 서버 앞단 Cloudflare 가 원본 응답을 기다리다 끊은 것이다. `qwen3-vl` 은
thinking 모드로 사고과정(`reasoning`)을 길게 뱉느라 느리다. 되살리려면 thinking
을 끄는 옵션을 먼저 확인해야 한다.

이 제약 때문에 함께 손본 것:

- 읽기 타임아웃 300초 → **90초**. Cloudflare 가 약 100초에 끊으므로 그 전에
  포기해야 다음 모델로 넘어간다. (기존 300초 설정이 "얼굴 기본 정보 분석 중"
  에서 하염없이 멈춰 있던 직접 원인이었다.)
- 스트리밍 수신으로 전환. 첫 조각이 곧바로 흘러나오므로 524 를 피할 수 있다.
  스트리밍 결과가 비면 일반 방식으로 자동 재시도한다.

**어떻게 검증했나**

- 웹소켓으로 실제 세션을 붙여 스크립트를 실행 → `FINISHED_SUCCESSFULLY`,
  요소 12개 렌더, 예외 0건.
- `PYTHONIOENCODING` 없이 실행해도 이모지 로그가 정상 출력됨을 확인
  (cp949 크래시 재발 없음).
- 앱 소스에서 실제 관상 프롬프트를 그대로 추출해 서버에 태운 결과,
  `성별 / 나이대 / 현재 직업 / 어울리는 직업` 4개 항목이 형식대로 반환됨.

**남은 것**

- 실사용 사진으로 긴 본문(1200자 이상) 생성까지의 최종 확인.
- `qwen3-vl:32b` thinking 비활성화 검토.
